# מעבד ספרים

אפליקציה מקומית בקובץ יחיד (`book_ai.py`) לעיבוד ספרים (EPUB, PDF, MOBI) באמצעות מודלי שפה, עם החזרת EPUB תקין.

## התקנה והרצה

    python -m venv .venv && source .venv/bin/activate     # ב-Windows: .venv\Scripts\activate
    pip install -r requirements.txt
    cp .env.example .env                                  # והכנס מפתחות (אופציונלי)
    python book_ai.py                                     # http://127.0.0.1:8765

- פייתון 3.9 ומעלה.
- ל-MOBI מומלץ להתקין Calibre (הפקודה `ebook-convert` ב-PATH). בלעדיו משתמשים בספריית `mobi` כגיבוי, באיכות נמוכה יותר. אם אין אף אחד מהם מוצגת הודעת שגיאה עם הוראות.
- בדיקת EPUB רשמית: הגדר `EPUBCHECK_JAR=/path/epubcheck.jar` (נדרש Java), אחרת רצות רק הבדיקות הפנימיות.
- פקודות נוספות: `python book_ai.py test` (בדיקות), `python book_ai.py samples` (קבצי דוגמה), `--port`, `--no-browser`.

## ספקים

| ספק | מפתח | הערות |
|---|---|---|
| Gemini | `GEMINI_API_KEY` | פלט JSON מובנה |
| OpenAI | `OPENAI_API_KEY` | פלט JSON מובנה |
| Anthropic | `ANTHROPIC_API_KEY` | פורמט רשימה |
| OpenRouter | `OPENROUTER_API_KEY` | פורמט רשימה |
| Ollama | ללא | מקומי, דבר לא נשלח החוצה |
| מותאם אישית | `CUSTOM_API_KEY` (אופציונלי) | נקודת קצה תואמת OpenAI, למשל שרת מקומי |

המפתח שמוזן בממשק נשמר בזיכרון הסשן בלבד. סימון "שמור מוצפן" שומר אותו מחוץ לתיקיית הפרויקטים (`~/.book_ai`, דורש `cryptography`).

### הוספת ספק חדש

יורשים מ-`AIProvider` בקובץ, מממשים `list_models` ו-`complete` (ומחזירים `(טקסט, {"in": n, "out": n})`), מסווגים שגיאות עם `classify_http_error`, ורושמים במילון `PROVIDER_CLASSES`. לוגיקת עיבוד הספר לא משתנה.

## איך זה עובד (בקצרה)

1. **מודל פנימי עם הפניה למקור.** כל כותרת, פסקה, פריט רשימה, ציטוט, הערה ותא טבלה מקבלים מזהה (`c03_e017`), סוג, רמה והפניה מדויקת לצומת (קובץ + נתיב + אינדקס רצף בתוך הצומת).
2. **החלפה נקודתית.** הפלט הוא עותק של הקובץ המקורי שבו מוחלף רק הטקסט. CSS, גופנים, תמונות, כריכה, ניווט, מטא־דאטה וקישורים נשארים. קבצים שלא שונו מועתקים בייט־בייט.
3. **עיצוב בתוך פסקה.** הדגשה, הטיה, קישורים, הפניות להערות, כתיב עילי/תחתי ושבירות שורה הופכים לתגיות ממוספרות (`<b1>`, `<a3>`, `<n4/>`). התכונות המקוריות נשמרות בצד. אחרי התשובה בודקים שכל תגית חזרה פעם אחת ושהקינון תקין.
4. **פרוטוקול ואימות.** מקטע נשלח כרשימת רכיבים (או JSON). כל תשובה נבדקת: מספר, מזהים, סדר, סוגים, רמות, תגיות, תוכן חיצוני, ריקנות, אורך חריג, מספרים ומונחי מילון. כשל גורר ניסיון עם הודעת תיקון, אחר כך פיצול המקטע (עד רכיב אחד), ורק אז סימון.
5. **חלוקה למקטעים.** לפי רכיבים בלבד, בתוך פרק. פסקה ארוכה מפוצלת לפי משפטים (בלי לחתוך תגית פתוחה) ומוחזרת כפסקה אחת.
6. **מילון מונחים וזיכרון תרגום.** המילון (עם נעילה והצעות אוטומטיות) נשלח למודל רק במה שרלוונטי למקטע. זיכרון התרגום משתמש שוב בתרגום של רכיב זהה בלי בקשה חדשה.
7. **ניסיונות חוזרים והמשך.** נסיגה מעריכית על מגבלת קצב, שגיאות שרת ו-timeout. המצב נשמר בכתיבה אטומית בתיקיית `data/projects/<id>` ואפשר להמשיך אחרי סגירה או קריסה בלי לשלוח שוב מקטעים שהושלמו.
8. **יומן.** חלונית בזמן אמת, קובץ `log.jsonl` לכל פרויקט, ומפתחות מוסרים מכל שורה.
9. **RTL.** בתרגום בין כיוונים: `lang`/`dir`, `page-progression-direction`, היפוך מאפייני CSS תלויי כיוון בלבד, ועטיפת מילים לועזיות ב-`bdi`.

## מגבלות ידועות

- איכות ה-PDF אינה מובטחת (שחזור מבנה בהיוריסטיקות). PDF סרוק נדחה (אין OCR). PDF בעברית/ערבית עלול לצאת עם סדר תווים הפוך.
- MOBI תלוי בכלי ההמרה. לעיתים סימון הכותרות הולך לאיבוד כבר בקובץ ה-MOBI עצמו.
- "תקציר הפרק הקודם" הוא חילוץ מכני (כותרת, תחילת הפרק וסופו), לא תקציר של המודל.
- בבקשות מקבילות העקביות פחותה. להפעיל "עקביות מרבית" לעיבוד לפי הסדר.
